# KoeLog

会議録音の文字起こしツール。ブラウザから音声をアップロードするだけで、タイムスタンプ付きテキストに変換します。

## セットアップ

```bash
pip install -r requirements.txt
```

## 起動

```bash
python -m uvicorn app:app --host 0.0.0.0 --port 8000
```

初回起動時にWhisperモデル（約500MB）がダウンロードされます。

## 使い方

1. ブラウザで http://localhost:8000 にアクセス
2. 音声ファイルをドラッグ&ドロップまたは選択（複数可。追加選択すると一覧の末尾に積まれます）
3. 「まとめて送信」をクリック（1件ずつ順番に送信され、受付順のキューに入ります）
4. 完了したら結果をダウンロード

### キュー処理

- サーバー側は FIFO キュー＋ワーカースレッド（既定 1 本、`config.py` の `WORKER_COUNT`）で受付順に処理します
- 処理中でも追加アップロードできます。追加分はキューの末尾に入ります
- ジョブ一覧の状態は「待機 n 番目 / 処理中 / 完了 / 失敗」で表示されます
- 待機中のジョブは「取消」でキューから外せます（後続の順位は繰り上がります）。処理中のジョブは取消・削除できません

## 精度と時間のバランス（4段階）

アップロードのたびに「精度と時間のバランス」を4段階から選べます（既定は段階3）。
段階ごとに使う Whisper モデルと探索の深さが変わります。定義は `presets.py` にあります。

| 段階 | 名前 | モデル / beam | 1時間の会議の目安 | メモリ目安 |
|---|---|---|---|---|
| 1 | 急ぎ（下書き） | small / 1 | 約10分 | 約750MB |
| 2 | 速い | medium / 1 | 約34分（未実測の見込み） | 約1,800MB |
| 3 | 標準（これまでと同じ） | medium / 5 | 約42分 | 約1,800MB |
| 4 | 高精度（いちばん精度が高い） | large-v3 / 1 | 約75分（未実測の見込み） | 約3,400MB |

- **段階4がいちばん精度が高い段階**です
- **段階3はこれまでの KoeLog と同じ設定**です（`medium` / `int8` / `beam_size=5`）
- 既定の段階は管理画面で変更できます。変更は次のジョブから有効です
- **所要時間の目安は実機で測った値ではありません。**実際のジョブが2本たまると、
  そのサーバーでの実績に自動で切り替わります（管理画面の「時間の根拠」欄で確認できます）。
  実績の倍率はモデルの読み込み時間を除いた値で、120秒以上の音声からのみ学習します
- 段階4 は `large-v3` を使うため、**初回は約3.1GBのダウンロード**が走ります。
  取得済みかどうかは管理画面の表で確認できます。ダウンロード中はジョブ一覧に
  「モデル準備中」と表示されます
- モデルはメモリに1個だけ保持します（`config.py` の `MODEL_CACHE_SIZE`）。
  これが1個ぶんのメモリで済むのは `WORKER_COUNT = 1` のときだけです

### 精度について

段階ごとの精度は、10分の会議音声を人が修正した原稿と突き合わせて比較しました。
**効いたのはモデルの大きさで、beam を深くしても精度は上がりませんでした。**

- `medium` は beam 1 で CER 20.9%、beam 5 で 23.5%（深くして悪化）
- `large-v3` は beam 1 で 18.1%、beam 5 で 18.4%（冒頭60秒を除いた誤り率）

このため、もとあった段階5（`large-v3` / beam 5）は 2026-11-20 に廃止しました。
段階5 は冒頭37秒を丸ごと落とし、代わりに `initial_prompt` の一部
（「ビジネス用語が含まれます。」）を出力しており、遅いだけで精度を買えていませんでした。
**番号は振り直していません**（`settings.json` の `quality_stats` に段階ごとの
所要時間の実績が貯まっているため、振り直すと実績が別の段階の値に化けます）。
古い `"5"` のキーが残っていても無視されます。
`quality_level=5` が送られてきた場合は、他の不正な値と同じく既定の段階に落ちます。

ただし比較に使った原稿は「文字起こしの出力に人が修正を入れたもの」であり、
独立した正解ではありません。元の出力が丸ごと落とした発話は原稿側にも無いため、
実際の取りこぼしは測定値より多い可能性があります。

## 保存先の変更（管理画面）

http://localhost:8000/admin の「保存先」でアップロード先・結果ディレクトリを指定できます。

- 絶対パスで指定します（`D:\KoeLogData\uploads` や UNC パス `\\server\share\koelog\results` など）。相対パス、`..` を含むパスは拒否されます
- 空欄なら既定（アプリ直下の `uploads/`、`results/`）を使います
- 「接続テスト」で一時ファイルの作成→削除を行い、OK／権限なし／存在しない を表示します。「存在しない場合は作成する」にチェックすると接続テスト時にフォルダを作成します
- 設定は `settings.json` に保存され、次のジョブから有効です（処理中・待機中のジョブは受付時点の保存先のまま）

## 検証用モック

`KOELOG_MOCK=1` を付けて起動すると Whisper モデルを読み込まず、各ジョブは数秒待ってダミーの文字起こし結果を書きます（faster-whisper / ffmpeg が無い環境での動作確認用。既定は本物の Whisper）。

```bash
KOELOG_MOCK=1 python -m uvicorn app:app --port 8000
```

## 対応形式

mp3, wav, m4a, ogg, flac, webm

## 動作環境

- Python 3.9+
- CPU動作（GPU不要）
- メモリ: 4GB以上推奨
